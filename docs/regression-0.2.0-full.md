## 2. 测试环境说明

### macOS 真实环境

- macOS 27.2.1、Apple Silicon；Node 26.12.0；Subversion/svnadmin 1.14.5。
- 真实 CC GUI 1.2.5、WebKit，安装插件 0.2.0；通过原生 AX、键鼠和截图执行，没有通过内部 IPC 或宿主 store 代替操作。
- 服务回归在真实 macOS 文件系统与本地 file:// SVN 仓库中运行，创建真实修订、锁和三类冲突；SDK 桥接由测试适配器调用 execFileSync。故障注入、API 适配器与真实原生交互在记录中分别注明。
- 既有 UI 用例使用 JSDOM/React，不能称为全部原生 UI 实测。原生仅执行 NATIVE 列出的项目。
- 实际插件已经恢复 0.2.0 启用状态，原 host-wc 可读取，缩放恢复 100%；升级夹具下载目录已清理。宿主按既有规则保留卸载数据，未冒充完成 30 天后的清理验收。

### Windows 模拟环境

- 在同一 macOS Node 进程中运行同一份原始插件代码，不伪造真实 Windows 操作系统。
- 工作副本输入为 `C:\回归 空格\wc`，桥接将该路径及混合分隔符映射到隔离 macOS 工作副本；Windows 空设备 `NUL` 映射到 `/dev/null`。
- SVN XML 的 wcroot/entry 路径改写为 Windows 路径，输出换行为 CRLF，再交给插件原始解析逻辑。UNC、盘符、大小写等另有字符串断言。
- 实际 SVN 文件与仓库操作仍由 macOS SVN 执行；NTFS、Windows CRT/ANSI、SlikSVN 参数解析、WebView2、系统剪贴板、DPI、ACL 和安装器均未仿真。
- 权限/依赖/网络/证书/超时为明确错误注入；快捷键为 KeyboardEvent；剪贴板为接口桩。其通过只代表插件处理预设输入的能力。
- 新测试适配器透传 options.env 并合并继承环境；既有 extended 测试桥接未透传 env 的历史缺口仍存在，不把其结果当作环境一致性证据。

## 5. 跨平台差异分析

- 同一份入口在当前两种后端配置下，常规服务流程的断言一致；Windows 路径映射、CRLF 和错误处理未发现本轮新增差异。
- macOS 实际中文文件读写、中文提交、只读文件拒绝均通过；Windows 对应成功是 macOS 后端映射结果，不能推导 Windows 字符转换或 ACL 正确。
- Cmd+Enter/Ctrl+Enter 的组件逻辑均通过；系统快捷键抢占、布局、输入法仍不在模拟范围。
- 正常剪贴板路径原生 macOS 成功；两端注入全部失败时均无可观测错误，属于共享逻辑问题而非仅 Windows 问题。
- macOS 原生安装、升级、停启、卸载已执行；Windows 仅模型通过，不能据此承诺无句柄、进程或注册信息残留。
- 当前是固定版本功能验收；未运行旧版完整对照套件，不能把所有新发现问题认定为 0.2.0 新引入的回归。

## 7. 最终结论

- 已把全部已有模块纳入测试范围并执行可运行的主流程，没有将 Windows 范围降为抽样；无法仿真的系统项及未执行组合明确保留。
- **本轮全覆盖验收不通过**：104 条通过不能抵消 3 条失败和 12 条未覆盖。
- macOS 常规 SVN 服务与本轮列出的原生生命周期检查通过；Windows 仅当前模拟覆盖范围通过。
- **不建议据此签署“跨平台全功能无差异、可无条件发布”的结论。** 新发布前至少处理 D-01 并回归，明确处理文档差异，补齐所列适用的真实宿主与系统测试；历史 Windows 两项故障保持开放。
- 本轮不改变已发布 Release、市场索引或 README。所有结果为本次实测记录，不以历史成功替代当前执行，也不以模拟成功掩盖历史真实失败。
