# macOS 与 Windows 兼容改造及回归记录

日期：2026-11-19。插件入口保持单文件 ESM，沿用原权限、命令参数数组及核心功能。

**最终状态：主要兼容改造已完成；两平台各两轮核心回归通过，但 Windows 中文参数及 @ 前空格仍有已知失败，未达到所有边界行为完全一致的验收标准。**

## 平台相关变更清单

| 范围 | 发现与处理 |
| --- | --- |
| 状态路径 | 原实现仅匹配 `/`，导致 Windows 状态条目丢失。统一 Windows 分隔符、盘符及大小写后检查目录边界，保留返回文件名的大小写。支持 UNC；拒绝将相邻前缀目录认作子目录。 |
| 工作副本元数据 | 支持反斜杠目录名称与等价根路径比较，避免额外读取与错误名称。 |
| 路径输入 | 拦截盘符相对路径、目录穿越和 NUL；Windows 路径额外拒绝控制字符（含换行）、保留设备名、非法字符、尾点及尾空格。macOS 合法的 `?` 文件名仍允许。 |
| 写操作互斥 | Windows 等价路径使用统一键，避免大小写或分隔符变化绕过同一路径的互斥。未解决符号链接、映射盘与 UNC 别名。 |
| 空设备 | Windows UNC 与盘符路径均使用 `NUL`；macOS 沿用 `/dev/null`。 |
| 测试夹具 | Windows 使用合法文件名测试忽略规则；macOS 保留通配字符文件名测试。Windows 核心回归使用 ASCII 路径／参数；中文真实检出与 @ 前空格另有独立 TODO 失败用例，不算通过。比较命令目标时兼容 Windows 路径，临时目录先 realpath 解析 8.3 短路径别名，扩展测试结束删除临时仓库。 |
| svn:ignore 换行 | Windows 真实回归发现旧值含 CRLF 时追加 LF 规则导致 E135000；追加前统一旧值为 LF，保留规则语义。 |
| 换行与打包 | 新增 CRLF 入口加载、清单复制、激活注册与模拟卸载清理测试。无构建、无插件自带原生模块或二进制。 |
| CI | 新增 macOS／Windows 矩阵，各执行两轮完整回归，使用 Node 22、真实 SVN／svnadmin 与模拟宿主。 |

## 静态检查结论

- 插件通过宿主 `plugin_exec_run` 传递 `bin: svn` 和参数数组，无 Shell 拼接、chmod、POSIX 安装脚本或自行发信号逻辑。进程发现、输出解码、超时与进程回收由宿主负责。
- 沿用 `LC_ALL=en_US.UTF-8`；已确认 SlikSVN 1.14.5 在 CI 默认 Windows 代码页下将中文参数转成 `?`，中文目录检出失败（E720123）。不能将 LC_ALL 当作 Windows Unicode 保证。
- 代理、认证和证书沿用本机 SVN 配置，不复制 macOS 配置路径，不关闭证书验证。
- 不自动修改文件权限、不删除失败检出的目标、不截断长路径。长路径最终取决于系统、宿主和 SVN 客户端能力。
- macOS 不强制折叠路径大小写，以免破坏大小写敏感卷。Windows 按常见的不区分大小写文件系统匹配；启用目录大小写敏感的 NTFS 场景待补测。

## 已知未解决问题

- **Windows 非当前代码页字符：实测失败，未解决。** Windows Server 2025、SlikSVN 1.14.5 默认代码页下中文检出目录丢失字符。当前 SDK 仅支持 bin／args／env／timeoutMs，不支持写 UTF-8 targets 文件或设置 cwd，因此不能在插件内可靠绕过客户端的 ANSI 参数转换。需要使用支持 Unicode 命令行的 SVN 分发／UTF-8 系统环境，或升级宿主能力后补测。不可将 ASCII 核心测试通过理解为中文行为一致。独立中文测试以 TODO 保留真实失败，不计为通过。
- **Windows 检出目录 `space @wc`：实测创建为 `space@wc`，未解决。** 为目录追加空 peg 会实际创建 `space @wc@`，已撤回该实验以保持检出语义。核心流程使用 `space dir@wc` 验证常规空格和 @；特殊相邻空格案例单独保留 TODO，不能视为路径完全一致。
- 参考 [Apache Subversion 命令行编码接口](https://subversion.apache.org/docs/api/latest/svn__cmdline_8h.html)；实际行为以本文 CI 日志为准。
